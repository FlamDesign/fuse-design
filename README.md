# Flam UI kit

shadcn/ui component reference and sample screens for the Flam platform.
Vite + React 19 + Tailwind v4, Radix base, Rhea style, Hugeicons, Rethink Sans, shadcn/typeset at 16px.

## Run

```bash
npm install
npm run dev          # local reference site
npm run build        # production build with hash routing
npm run build:hosted # few-file build used for the hosted Claude artifact
```

`npm run build -- --mode artifact --outDir dist-artifact` builds the hosted variant (in-memory routing).

## Theme

All tokens live in `src/index.css` under `:root` and `.dark`. Change values only; the names are what every
component reads. `THEME-CHANGES.md` lists each value against the shadcn default.

## Structure

- `src/components/ui` · the 63 shadcn components
- `src/registry.ts` · title, description and exports for each component page
- `src/pages/docs` · components index and the per-component page (preview, code, installation, usage)
- `src/pages/components` · the preview sources, grouped by category
- `src/pages/apps` · sample screens: dashboard, campaigns, creative editor, flow builder, asset library, inbox, assistant, settings
- `src/layouts/app-layout.tsx` · shell, `src/nav.ts` · sample screen navigation

## Edits to generated components

- `sonner.tsx` reads the local theme provider
- `spinner.tsx` prop type fix
- `slider.tsx` labels each thumb
- `combobox.tsx` labels the trigger button
- `sidebar.tsx` and `theme-provider.tsx` tolerate blocked cookies and storage
- `carousel.tsx`, `use-mobile.ts` lint fixes

## AI Elements

The 21 AI Elements patterns from shadcn/ui, plus the `shimmer` and `scroll-fade` utilities and the `@shadcn/helpers` chat helpers, live under `/ai`.

- Pattern sources are in `src/examples/ai`, generated from the shadcn/ui repo by `tools/gen_ai.py` (paths rewritten, Lucide icons mapped to Hugeicons).
- They are compositions of components already in `src/components/ui`. There is no extra package to install for the patterns themselves.
- Demos and the Assistant screen run on the Vercel AI SDK (`ai`, `@ai-sdk/react`) with scripted conversations from `@shadcn/helpers/ai-sdk`, so no model or API key is needed.
- `src/components/markdown.tsx` renders streamed replies with Streamdown and the kit's typeset styles.

## Component examples

Every component page ends with an Examples section holding the variations from the shadcn/ui docs: 440 examples across 63 components.

- Sources are in `src/examples/ui`, generated by `tools/gen_ui.py` from the shadcn/ui repo. Lucide and Tabler icons are mapped to Hugeicons, `next/link` and `next/image` become plain elements, and remote photos are replaced with local placeholders in `public/`.
- The folder is excluded from lint because it is upstream code. Do not edit it by hand; rerun the generator.
- Left out: right-to-left examples, the full-page sidebar block, and the TanStack Table v9 data table demo (the kit pins v8 and has its own data table).

## Regenerating upstream examples

`tools/gen_ui.py` and `tools/gen_ai.py` rebuild `src/examples` and the two generated registries from a clone of `shadcn-ui/ui`. Point `SHADCN_UI_V4` at its `apps/v4` folder, run the script with Python 3, then run Prettier on `src/examples`.

## The `@flam` registry

This repo is also a shadcn registry. Other Flam projects install the theme, Flam's versions of edited components and the design rules from it. It is public, so no token is needed.

### Use it in a project

1. Add the namespace to the project's `components.json`:

```json
{
  "registries": {
    "@flam": "https://raw.githubusercontent.com/FlamDesign/fuse-design/main/r/{name}.json"
  }
}
```

2. Install the base:

```bash
# new project, after `npx shadcn@latest init`
npx shadcn@latest add @flam/base

# existing project: replace its tokens and the edited components
npx shadcn@latest add @flam/base --overwrite
```

3. In an existing project, replace hard-coded colours (hex values, Tailwind palette classes) with tokens. Projects already on stock shadcn token names need no other change.

4. Point coding agents at the rules: add `@FLAM-DESIGN.md` to the project's `CLAUDE.md` or `AGENTS.md`. Cursor picks up `.cursor/rules/flam-design.mdc` on its own.

### Items

| Item | What it installs |
|---|---|
| `@flam/base` | Theme, all edited components, rules. Start here. |
| `@flam/theme` | Colour tokens for light and dark, the brand colour, Rethink Sans, base styles |
| `@flam/rules` | `FLAM-DESIGN.md` and a Cursor rule |
| `@flam/tabs`, `card`, `button`, `badge`, `trace`, `slider`, `combobox`, `calendar`, `command`, `sonner`, `spinner`, `sidebar`, `carousel` | Flam's version of that component |
| `@flam/theme-provider`, `use-mobile`, `highlighter` | Supporting files |

Everything else comes from the stock registry as usual: `npx shadcn@latest add dialog`.

### Keeping Flam's versions

- Do not pass `--overwrite` when adding stock components. Stock components such as `input-group` depend on stock `button`, and `--overwrite` would replace Flam's copy.
- If that happens, run `npx shadcn@latest add @flam/base --overwrite` again.
- Theme updates do not reach a project by themselves. Re-run `npx shadcn@latest add @flam/theme` to pull new values.

### Publishing a change or a new component

1. Edit or add the source under `src/`.
2. Add or update its entry in `registry.json` (`files`, `dependencies`, `registryDependencies`). If the component belongs in the base, add its file to the `base` item too.
3. Run `npm run registry:build` and commit the regenerated `r/` folder.
4. Merge to `main`. The registry URL serves from `main`.

A custom component such as the player UI is one more `registry:ui` or `registry:block` item. Use `@flam/...` in `registryDependencies` for Flam's versions and bare names for stock ones.

### Product namespaces

To keep product components separate but reusable, give each product a folder and its own output, for example `registry/flicks/registry.json` built to `r/flicks/`, and register it as `@flam-flicks` with the URL `.../main/r/flicks/{name}.json`. Any project can list several namespaces and install from each. Move a component to `@flam` once a second product needs it.

### Agents

Three pieces make a coding agent use Flam's components correctly. Set them up once per project.

1. **shadcn skill.** General shadcn/ui practice: which component fits which need, how to compose forms, cards and dialogs, styling conventions.

```bash
npx skills add shadcn/ui
```

2. **shadcn MCP server.** Lets the agent search and install from the stock registry and from `@flam`. It reads the `registries` block in `components.json`.

```bash
npx shadcn@latest mcp init --client claude   # or cursor, vscode
```

For Claude Code this writes `.mcp.json`; commit it so everyone on the repo gets the server. This repo already has one.

3. **Flam rules.** `npx shadcn@latest add @flam/rules` installs `FLAM-DESIGN.md` and a Cursor rule. They cover only what is specific to Flam: tokens, the brand colour and preferring `@flam` components. For Claude Code or Codex, add the line `@FLAM-DESIGN.md` to the project's `CLAUDE.md` or `AGENTS.md`.

## Tokens

`packages/tokens/theme.css` is the single source of truth for colour tokens. Edit values there and nowhere else.

- The kit imports it from `src/index.css`.
- `npm run registry:build` copies it into the `@flam/theme` registry item.
- It is also an npm package (`packages/tokens`). A project that imports `@flam/tokens/theme.css` picks up new values with a version bump; a project that installed `@flam/theme` through the shadcn CLI has to re-run `npx shadcn@latest add @flam/theme`.

To release new token values: edit `theme.css`, bump the version in `packages/tokens/package.json`, run `npm run registry:build`, merge, then `npm publish` from `packages/tokens`.
